## Architecture sketch

- **Auth**: Supabase Auth. Google OAuth (preferred) + email magic link
  with a fallback **8-digit OTP code** input (Supabase's project setting
  is 8 digits — input field's maxlength is set to 8). `is_email_invited`
  RPC + `claim_invited_team` RPC handle allowlist + auto team-assignment.
  Public sign-up is disabled in the dashboard so `invited_emails` is the
  real gate.

- **Data layer**: All league state in Supabase tables (`trades`,
  `keeper_selections`, `league_state`, `callup_overrides`, `activity_log`,
  `owners`, `invited_emails`, `trade_proposals`, `trade_proposal_messages`,
  `roster_moves`). `db.js` keeps an in-memory cache; deep-clones on
  read for mutation-prone caches; writers are optimistic with revert on
  failure.

- **MiLB roster auto-derivation**: `applyRosterAdjustments()` in `app.js`
  rebuilds every team's `minors`/`callups` arrays at the start of every
  `switchTab` from a static anchor (`data.js`) + the trades log + the
  `roster_moves` log. A trade involving a `minor`/`callup` asset moves
  the player automatically; a Call Up moves them minors→callups; a Send
  Down moves them back with a `sentDown:true` flag. Re-applies live
  stats from `PLAYER_STATS` at the end so daily-refreshed careerAB/IP
  override stale data.js values.

- **Realtime**: One channel for `postgres_changes` on data tables, one
  for presence. Refreshes the active tab on any change but skips if a
  form input is focused or a modal is open. Separate filter on `owners`
  (id = current user) so role changes propagate.

- **Realtime presence**: `_setupPresence` puts each owner on a shared
  channel with their team_id; header shows "X online". Requires Supabase
  JS ≥ 2.50 — we're on 2.74.0.

- **Activity feed**: every meaningful action calls `logActivityAsync` →
  row in `activity_log`. Activity tab groups by Today/Yesterday/date.
  RLS rejections surface as a toast.

- **Daily digest**: `daily_report.py` queries last 24h of activity,
  emails commissioners via Gmail SMTP. Writes a fallback file to /tmp.

- **Sync failure signal**: scripts write `/tmp/fantasy-league-sync-failed`
  and fire a macOS notification on any failure. Cleared on success.
  Check that file first if snapshots look stale.

- **XSS hardening**: `escapeHtml()` on user strings into `innerHTML`,
  `escapeJsString()` on inline `onclick`/`onchange` handlers.

## Sheet → data.js sync (minors + callups)

The league's published Google Sheet is the canonical source for minors
and called-up players. `scripts/sync_minors_from_sheet.py` parses the
CSV view, rewrites the `minors` and `callups` arrays in `js/data.js`
for each of the 12 teams, **leaving `majors` (keepers) alone** since
those are still hand-edited.

- **Year format**: sheet uses `2026m`; script strips trailing `m`.
- **`careerStat` is intentionally ignored from the sheet** (often
  stale). Defaults to 0 in the snapshot; `applyLivePlayerStats()`
  overlays the live MLB Stats API number at runtime.
- **`statType`** (AB vs IP) is preserved from existing data.js when
  the player's name still appears, otherwise pulled from
  `PLAYER_STATS.players[name].statType`, otherwise defaults to "AB".
- **Dedupe**: if a player appears in both the sheet's "Minors" and
  "Called up" sections (sheet drift after a send-down that didn't get
  removed from callups), we prefer minors.
- **Regex bug history**: an early version of `replace_array` used
  `[\s\S]*?\n\s*]` to find array boundaries; this clobbered teams whose
  arrays were inline-empty (`callups: []`) by consuming forward to the
  *next* array's closing bracket, eating that team's minors. Current
  regex uses `[^\]]*\]` which stops at the first `]`. **Don't reintroduce
  the greedy version.**

To run manually: `python3 scripts/sync_minors_from_sheet.py`.

The script is **not yet wired into nightly_sync.sh** — running on
demand only. If you want it nightly, add a line to `nightly_sync.sh`
between the player-stats sync and the git-push block.

## CommishAI (Supabase Edge Function)

Floating 💬 button at bottom-right (when signed in) opens a chat panel.
Backed by `supabase/functions/rules-bot/index.ts`.

### Setup

`supabase/functions/rules-bot/SETUP.md` has paste-ready instructions.
Required Supabase Edge Function secrets:

- `GROQ_API_KEY` — from https://console.groq.com/keys (free tier)
- `COMMISHAI_DAILY_TOKEN_CAP` — optional, defaults to 2,000,000

### How it works

- Frontend (`js/rules-bot.js`) sends:
  - `question` (string, ≤2000 chars)
  - `history` (last 4 turns)
  - `myRoster` — asker's full team with `keeperLastYear` pre-computed
    via `getContractStatus` / `getMinorLeagueContractStatus` (the bot
    reads this directly; **never asks it to derive eligibility from
    `yearAcquired`**)
  - `leagueIndex` — compact per-team string array of all other teams'
    players (e.g. `matt ML: Workman$15→28, ...`) for cross-team queries
- Edge function:
  - Verifies JWT → looks up team + commish flag in `owners`
  - Pre-flight: reads daily usage from `league_state.commishai_usage`,
    rejects if over cap (UTC reset)
  - Builds system prompt: instructions + RULES_DIGEST (compact, hardcoded
    in source — full constitution lives in the DB / Rules tab) +
    SITE_GUIDE + asker's roster + leagueIndex
  - Tries `llama-3.1-8b-instant` first, falls back to
    `llama-3.3-70b-versatile` on 429/413/404/400-decommissioned
  - Post-call: adds tokens to `commishai_usage`
- **Error masking**: non-commissioners see *"I don't have the answer.
  Please ask the commissioner."* on any upstream failure; commissioners
  see the full error text for debugging.

### Why Groq (and history)

We tried in order: Anthropic Claude Sonnet/Haiku (cost) → Gemini Flash
(account had `limit:0` for free tier) → Groq Dev Tier (not generally
available right now) → **Groq free tier** with the 8B model first to
fit the tight TPM ceilings. If Groq's free TPM keeps biting, the
cleanest swap is Gemini paid tier — see commit `12d2eb3` for a
reference implementation of the Gemini OpenAI-compatibility endpoint
(env var, URL, models). The rest of the function logic is identical.

### Iteration tips

- The system prompt is sized to fit ~5–6k tokens total (Groq free
  tier 8B has 6k TPM). Don't add big new context blocks without
  removing something else.
- `_compactRoster` and the per-team line format (`teamId ML: Name$P→YY`)
  are the result of multiple compression passes. Keep them tight.
- The bot is told to **filter on `keeperLastYear`** for keeper questions;
  if that field is missing for a player, the bot defers rather than
  guessing.

## PWA

- `manifest.json` + apple-touch-icon + favicon links + iOS meta tags
  in `index.html`.
- `service-worker.js` is **network-first** for same-origin requests,
  cache fallback for offline. Skips third-party (Supabase / Groq / ESPN).
- **Auto-update flow** (in the inline `<script>` at the bottom of
  `index.html`):
  - `reg.update()` on every launch + every hour
  - On `updatefound` → wait for `installed` state → postMessage
    `SKIP_WAITING` to the new SW
  - SW responds to that message by calling `skipWaiting()`
  - On `controllerchange` → page reloads once (guarded against loop)
  - Result: PWA users get fresh code without manual reinstall

If you change SW behavior itself, bump `CACHE_VERSION` in
`service-worker.js` so old caches get wiped on activate.

## Sticky team selectors

`_lastTeamSel = { eligible, keepers, rosters }` at module scope. Each
`update*View()` writes the dropdown's value into this map; `switchTab`
restores from it instead of always resetting to "all". Prevents
realtime echoes (which trigger `switchTab(currentView)`) from snapping
the user back to "All Teams" mid-edit.

## Activity-log undo (commish-only, every entry)

`undoActivityEntry(activityId)` in `app.js`:
- Deletes the activity_log row
- For roster moves (`player_called_up` / `player_sent_down`): deletes
  the underlying `roster_moves` row by id
- For Rule 5 picks: finds the matching pick in rule5 state, deletes
  the trade row, removes the pick
- For minors picks (`minors_pick_made` / `_passed`): pops from
  `draft.picks` / `draft.passed`
- For keeper / Rule 5 / trade-block toggles: flips the flag back via
  `setKeeperSelectionAsync`
- For `trade_recorded`: deletes the trade row by `payload.trade_id`
  (only present on trades created after the trade-id-logging change)
- For `callup_price_set`: deletes the override row
- For `keepers_locked` / `_unlocked`: flips the lock state
- For `commish_override`: clears the override for that player
- Other types (trade_edited, trade_deleted, draft_resets): only the
  log row is removed — the underlying change is destructive and isn't
  auto-reversed

## Outstanding bugs / known notes

- **Chatbot panel positioning regression history**: the `apply()` keyboard
  handler used to clear `panel.style.bottom` unconditionally on the
  "no keyboard" branch, which erased the panel's inline `bottom: calc(...)`
  and made the panel disappear when the user tapped the input on desktop.
  Current code (commit `a4cb9cb`) tracks override state via
  `_bottomBackup` / `_heightBackup` and only restores when actually
  overrode. **Don't go back to `panel.style.bottom = ""`.**
- **Chatbot disappearing on auth flicker**: `_watchAuth` used to call
  `_toggle(false)` whenever `currentOwner` was nullish for a tick (which
  happens during Supabase's onAuthStateChange await). Removed in commit
  `6981e0d`. The FAB still hides when truly signed out.
- **Player stats can lag if cron credentials regress**: see the
  cron-credential gotcha above. Keep an eye on `/tmp/fantasy-league-
  espn-sync.log` if syncs look stuck.

Knowingly accepted trade-offs (not bugs):

- **`is_email_invited` is anon-callable** — needed for the pre-login
  gate. Closeable via Edge Function if it ever matters.
- **One-sided trades require a `confirm()`** rather than a hard block —
  preserves the "gift" / salary-dump use case.
- **Auth `flowType: "implicit"`** — PKCE breaks cross-device magic-link
  clicks; implicit is the right call for a 12-person league.
- **Owner-initiated callup *prices*** — owners can call up via the app
  but setting a callup price still goes through the commish (callup
  prices are an offseason thing per league rules).
- **Send Down button hidden when player isn't on ESPN roster** — by
  design. The action requires the player to actually be on the team's
  ML roster on ESPN. If a fresh app-side Call Up hasn't synced to ESPN
  yet, the button won't show until the 15-min ESPN sync catches up.
