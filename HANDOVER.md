## Architecture sketch

- **Auth**: Supabase Auth. Google OAuth (preferred) + email magic link
  with a fallback **8-digit OTP code** input. `is_email_invited` RPC +
  `claim_invited_team` RPC handle allowlist + auto team-assignment.
  Public sign-up is disabled in the dashboard so `invited_emails` is the
  real gate. Auth email templates (magic link + invite) live in
  `email-templates/auth-*.html`; paste into the Supabase Email Templates
  panel when they change.

- **Data layer**: All league state in Supabase tables. `db.js` keeps an
  in-memory cache; deep-clones on read for mutation-prone caches; writers
  are optimistic with revert on failure. Current tables:

  - `owners`, `invited_emails` — auth / team allocation
  - `trades`, `trade_proposals`, `trade_proposal_messages` — trade flow
  - `keeper_selections` — eligible-keeper toggles (keeper / minor_keeper /
    rule5 / trade_block)
  - `roster_moves` — { kind: "callup" | "demote", player_name, team_id, at }
  - `callup_overrides`, `league_state` — JSONB state buckets
    (draft_2027, rule5, commish_overrides, workaround_overrides,
    keeper_deadline, constitution, **settings, keeper_price_exceptions,
    fees_paid, notify_marker, notify_draft_marker, snapshot_…**)
  - `activity_log` — every meaningful action; drives both the Activity
    tab and the notification fan-out
  - **`notification_prefs`** — per-team email + push prefs
    (`prefs.<eventKey>.{email,push}` + `prefs.draft_clock.<state>.{email,push}`
    + `prefs.inboxReads.<threadId>` for cross-device unread sync +
    `receive_all` flag — Jeff has it set to true)
  - **`push_subscriptions`** — per-device Web Push subscription rows
  - **`league_messages`** — message board: { team_id, user_id, body, created_at }

- **MiLB roster auto-derivation**: `applyRosterAdjustments()` in `app.js`
  rebuilds every team's `minors`/`callups` arrays at the start of every
  `switchTab` from a static anchor (`data.js`) + the trades log + the
  `roster_moves` log. A trade involving a `minor`/`callup` asset moves
  the player automatically; a Call Up moves them minors→callups; a Send
  Down moves them back. Re-applies live stats from `PLAYER_STATS` at
  the end so daily-refreshed careerAB/IP override stale data.js values.

- **Realtime**: One channel for `postgres_changes` on data tables, one
  for presence. Refreshes the active tab on any change but skips if a
  form input is focused or a modal is open. Separate filter on `owners`
  (id = current user) so role changes propagate. Channels added for
  `notification_prefs` (so cross-device inbox-reads + pref edits sync)
  and `league_messages` (so the message board updates without polling).

- **Realtime presence**: `_setupPresence` puts each owner on a shared
  channel with their team_id; header shows "X online". Requires Supabase
  JS ≥ 2.50 — we're on 2.74.0.

- **Activity feed**: every meaningful action calls `logActivityAsync` →
  row in `activity_log`. Activity tab groups by Today/Yesterday/date.
  RLS rejections surface as a toast.

- **Sync failure signal**: scripts write `/tmp/fantasy-league-sync-failed`
  and fire a macOS notification on any failure. Cleared on success.
  Check that file first if snapshots look stale.

- **XSS hardening**: `escapeHtml()` on user strings into `innerHTML`,
  `escapeJsString()` on inline `onclick`/`onchange` handlers.

## Sheet → data.js sync (minors + callups)

The league's published Google Sheet is the canonical source for minors
and called-up players. `scripts/sync_minors_from_sheet.py` parses the
CSV view, rewrites the `minors` and `callups` arrays in `js/data.js`
for each of the 12 teams, **leaving `majors` (keepers) alone** since
those are still hand-edited.

- **Year format**: sheet uses `2026m`; script strips trailing `m`.
- **`careerStat` is intentionally ignored from the sheet** (often
  stale). Defaults to 0 in the snapshot; `applyLivePlayerStats()`
  overlays the live MLB Stats API number at runtime.
- **`statType`** (AB vs IP) is preserved from existing data.js when
  the player's name still appears, otherwise pulled from
  `PLAYER_STATS.players[name].statType`, otherwise defaults to "AB".
- **Dedupe**: if a player appears in both the sheet's "Minors" and
  "Called up" sections, we prefer minors.
- **Regex bug history**: an early version of `replace_array` used
  `[\s\S]*?\n\s*]` to find array boundaries; this clobbered teams whose
  arrays were inline-empty (`callups: []`) by consuming forward to the
  *next* array's closing bracket. Current regex uses `[^\]]*\]` which
  stops at the first `]`. **Don't reintroduce the greedy version.**

To run manually: `python3 scripts/sync_minors_from_sheet.py`.

## Draft clocks (Minors + Rule 5)

4-hour pick clock; ticks only during 8 AM – midnight ET (overnight
blackout pauses automatically); commissioner can manual pause/resume.

**Client-side ticker** updates the visible countdown every second.
**Server-side cron** (`notify_draft_clock.py`, every 2 min) does TWO
things:

1. **Auto-skip** any expired pick: appends to `draft.passed`, resets
   the clock for the next pick, logs `minors_pick_auto_skipped`. This
   closes the gap when no commish has the draft tab open in a browser.
2. **Clock alerts**: sends email + push to teams whose pref toggle for
   their (in-hole / on-deck / on-clock) state is enabled. Idempotent
   via per-team per-state marker in `league_state.notify_draft_marker`.

## Notifications system

### Storage (in Supabase)

- `notification_prefs.prefs` — per-team JSON keyed by event. Each row:
  `{ email: "instant"|"daily"|"weekly"|"never", push: bool }`. Daily floor
  for keeper / Rule 5 / call-up / send-down / other teams' picks (no
  Instant option). Push only on real-time events.
- `notification_prefs.prefs.draft_clock.<state>.{email,push}` for in-hole /
  on-deck / on-clock alerts.
- `notification_prefs.prefs.inboxReads.<threadId>` — server-side mirror of
  the legacy localStorage read map, so the Trades unread badge clears
  cross-device.
- `notification_prefs.receive_all` — Jeff has this set, so the daily/weekly
  digest skips per-category filtering for him.
- `push_subscriptions` — one row per device-level Web Push subscription.

### Backend pipelines

| Script | Cron | Purpose |
|---|---|---|
| `daily_report.py` | 9pm daily | Per-team digest filtered by `prefs.<cat>.email == "daily"` (plus instant categories folded in). Jeff's `receive_all` row gets everything. |
| `weekly_report.py` | Sun 9pm | Same shape, 7-day window, `email == "weekly"`. |
| `notify_instant.py` | every 1 min | Polls `activity_log` since `league_state.notify_marker.last_seen_ts`. For each new event whose category supports "instant" (trade_proposal, trade_update, trade_message, trade_completed), fans out email + push to teams that opted in. Prunes 410-Gone push subs. |
| `notify_draft_clock.py` | every 2 min | Auto-skip + draft-clock alerts (above). |

All scripts share `_email_template.py` (HTML+text renderer matching the
digest mockup), `_notify_db.py` (Supabase REST + category mapping),
`_mail.py` (Gmail SMTP), `_push.py` (pywebpush via VAPID).

Generated once via `scripts/generate_vapid.py` (requires
`pip3 install --user py_vapid cryptography pywebpush`). Stored:
- Private key (PEM, `\n`-escaped on one line) in `scripts/.env` as
  `VAPID_PRIVATE_KEY`. Also `VAPID_SUBJECT="mailto:jwarshafsky@gmail.com"`.
- Public key (URL-safe base64) hardcoded into `js/app.js` as the

## Luxury Tax

Cap is **$350**. Per-player rules (simplified):
- **Keeper / auction pick** → their stored price (data.js `price` shifted
  by `(CURRENT_SEASON - 2026) × $2`)
- **Free agent** → flat $1
- **Minor-league call-up** → flat $1
- **Keeper Price Exception** (commissioner-set in Commissioner Tools) →
  always wins, regardless of contract type

Table includes per-team expandable breakdown (`<details>`) so the
commissioner can audit every contribution. Sorted by salary descending.

## Commissioner Tools

- **Set Year** — stores `currentSeason` in `league_state.settings`,
  `CURRENT_SEASON` is a `let` reconciled on every `switchTab`. Keeper
  prices bump $2/yr in-memory via `_applyPriceShiftToData` (idempotent +
  reversible — tracked by `_currentlyAppliedPriceShift`). Year-aware
  labels everywhere (nav, headers, tables).
- **Draft Roster Limits** — toggles in `settings.enforceRule5RosterSpot`
  / `enforceMinorsRosterSpot`. When on, `makeRule5Pick` / `makeDraftPick`
  block the on-the-clock team if their ML/MiL roster is full. Default OFF.
- **Keeper Price Exceptions** — per-player true-salary override. The
  exception replaces `basis.price` in `getEligiblePlayers` before
  contract math runs, so years-remaining and next-year-price respect
  the override.
- **Export contracts (.csv)** — every team's full roster with status,
  source, contract type, all flags (keeper / minor keeper / Rule 5 /
  trade block), price-exception flag, ESPN player ID.
- **Rollback (snapshots)** — manual snapshot + restore. Stores entire
  league state under `league_state` keys with `snapshot_<ts>` prefix.
  Restore wipes current data + reapplies snapshot; takes an auto-safety
  snapshot first.

## Things to watch when picking up

- **`?v=` cache buster**: every meaningful JS/CSS edit needs a bump.
  Currently at `?v=146`. PWA users now auto-update, but Safari /
  desktop visitors can still cache.
- **`scripts/.env` is gitignored** and contains secrets (`SUPABASE_SERVICE_ROLE_KEY`,
  `SMTP_USER`, `SMTP_PASS`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, ESPN cookies).
- **`/tmp/fantasy-league/`** is the dev preview mirror. **Manually rsync
  source to it after edits** if testing the local preview server.
- **GitHub Pages deploy is ~1 minute** after push.
- **Realtime WebSocket** is sensitive to Supabase JS version. Stick
  with 2.74.0 unless you have a reason; we had silent-empty
  `presenceState` for weeks on 2.45.4.
- **Edge function changes are NOT covered by `git push`** — the
  function deploys via the Supabase dashboard. Always remind Jeff to
  redeploy after edits to `index.ts`.
- **Service worker changes**: if you change `service-worker.js`,
  bump `CACHE_VERSION` (currently `the-league-v6`). Existing PWA users
  pick it up via auto-update on next launch.
- **Service worker push paths**: the SW uses absolute `/the-league/...`
  paths for icon/badge. If GitHub Pages base URL ever changes, fix
  those alongside the manifest.json `start_url`.
- **Schema additions need explicit GRANTs**: Supabase doesn't auto-grant
  new public-schema tables to `authenticated` / `service_role` in every
  project. Always include `grant select, insert, update, delete on
  public.<table> to authenticated; grant all on public.<table> to
  service_role;` in `schema.sql`. The notifications + message-board tables
  hit this — `notify_instant.py` 403'd until grants were added.
- **`_surfaceQuiet` for new tables**: when adding a table that's optional
  during rollout, route its `_fetchAll` result through `_surfaceQuiet`
  instead of `_surface` so a missing-relation error doesn't toast users.
- **Implicit invariants**:
  1. `LEAGUE_DATA.teams` (`data.js`) is the canonical 12-team list.
     IDs: `jeff, matt, jesse, sam, saxton, aj, corey, dave, josh-doug,
     larry, zack, glicksman`.
  2. `ESPN_ABBREV_TO_LOCAL` (`app.js`) maps live ESPN abbrevs.
     `HISTORICAL_ABBREV_OVERRIDES` covers older / former-team abbrevs
     for the trophy view.
  3. `CURRENT_SEASON` is a `let`, NOT a `const`. Default 2026, overridable
     via Commissioner Tools → Set Year (saved to `settings.currentSeason`).
     `DATA_JS_BASE_SEASON = 2026` is the immutable baseline.
  4. `DRAFT_YEAR = 2027` (the year being drafted for during 2026 season).
     Currently still a `const`.
  5. `LUXURY_TAX_CAP = 350`, `ML_ROSTER_MAX = 25`, `MIL_ROSTER_MAX = 10`,

## How to keep momentum

User likes a fast pace. Typical loop:
1. He describes a feature/bug (often briefly — read between the lines).
2. Make changes, bump `?v=N`, push.
3. Wait for GH Pages deploy via Bash run_in_background + an
   `until curl ... grep -q '?v=N'` loop.
4. Verify in his browser via `mcp__Claude_Preview__*` (he's signed
   in there as Jeff/commish; full DOM access).
5. Send a brief summary of what shipped + any "needs you to do" steps
   (SQL snippets, edge-function redeploy reminder, hard-refresh
   instructions).

He's collaborative and patient with diagnosis but doesn't want to
debug plumbing — own the investigation, surface the actual cause,
propose the fix.

**Batch when asked.** Sometimes he'll say "batch these before pushing"
— accumulate the changes locally and push once at the end.

**When luxury tax / contract math discrepancies come up**, simulate
the full resolveCostBasis logic in Python (post-draft ADD events
shift auction picks → FA $1) before claiming our values are correct.
Or just `mcp__Claude_Preview__preview_eval` against `getEligiblePlayers`
in the live app. The user has been right multiple times when our naive
diff said the live app was wrong.

If a problem recurs after a "fix" (chatbot disappears was the canonical
historical example), don't reach for the same pattern again. Keep
isolating: add tracking state, reproduce on Chrome MCP, check the
actual computed styles, look for whichever code path is closing /
hiding the thing.
