# The League — full bug audit, 2026-07-16

Four parallel review passes (core engine, cron/automation, Supabase security, caching/UI),
top findings independently re-verified. Verification level noted per item.
"LIVE-CONFIRMED" = demonstrated against the live system; "verified" = re-read/executed by
the lead session; "agent-confirmed" = confirmed by reviewer reading the code.

## Tier 1 — serious, fix before next live draft / soon

1. **Lost-pick race in the draft-clock cron** — `scripts/notify_draft_clock.py:324-360`, `js/db.js:948-965`.
   The cron fetches the whole `draft_2027`/`rule5` row, mutates for seconds, then upserts the
   full row with no version check; the browser writes the same way. A pick submitted between
   the cron's read and write is silently erased and the slot marked auto-passed.
   Found independently by two reviewers. *Fix: optimistic concurrency (version column or
   compare-and-swap RPC) on `league_state`, or make the cron re-fetch + diff before upsert.*

2. **Cron ignores trade-log pick ownership** — `scripts/notify_draft_clock.py:35-43` vs
   `js/app.js:4510-4544` (`getTradeLogOwner`). Picks traded via the in-app Trade Log alert the
   OLD owner ("on the clock" email to the wrong team); new owner gets nothing and can be
   auto-skipped; activity log attributes the pass to the wrong team. Found independently by
   two reviewers. `build_export.mjs` has the walk (but see Tier 3 divergences). *Fix: port
   `getTradeLogOwner` (incl. `pickOriginalOwner` pinning + `parseMilbPickValue`) into the cron.*

3. **Resume-from-pause corrupts the 4-hour clock across overnight blackouts** —
   `js/app.js:5255-5259` (`resumeDraftClock`), `js/app.js:10698-10702` (`resumeRule5Clock`).
   Resume shifts `startedAt` by active-ms in wall-clock space; if the shifted window crosses
   midnight–8AM ET the blackout is double-counted — a multi-day pause can expire the clock at
   the moment of resume, and the cron then auto-passes the pick. Reviewer executed the code
   numerically (verified: pause 1h-used overnight → resumes with 2h used). *Fix: store
   `activeElapsedAtPause` and reconstruct, instead of shifting startedAt.*

4. **Undo / un-pass / delete-pick / reopen-draft never reset the clock** —
   `js/app.js:4612-4628, 5294-5310, 5136-5143, 5112-5119, 10150-10167, 10772-10808`.
   The newly-current slot inherits a `startedAt` hours/days old; the 5-min cron auto-passes it
   almost immediately. Same family as the 7/16 phantom-email incident. (draft_2027's clock is
   currently nulled from today's cleanup, so reopen today is safe; the bug fires once picks
   resume.) *Fix: reset/null `clock` in every slot-reopening flow.*

5. **Public-key holders can trigger GitHub workflows and forge the scheduler heartbeat** —
   `supabase/pg_cron_setup.sql:78,107`. `revoke ... from anon, authenticated` doesn't remove
   the default PUBLIC execute grant, and both SECURITY DEFINER functions are exposed as
   PostgREST RPCs. **LIVE-CONFIRMED**: anon-key call to
   `rpc/dispatch_github_workflow {"workflow_file":"nonexistent-test.yml"}` returned success and
   wrote `league_state.pg_cron_heartbeat.lastWorkflow = "nonexistent-test.yml"` (harmless test;
   row self-heals on the next 15-min heartbeat). Impact: CI spam via stored PAT, heartbeat
   forgery masking real outages. *Fix: `revoke all on function ... from public;` for both, and
   re-run the setup SQL.*

## Tier 2 — real bugs, moderate urgency

6. **XSS via presence team name** — `js/app.js:11199, 11237` interpolate presence
   `teamName` (client-supplied via `db.js:664` `.track()`) into a `title` attribute without
   `escapeHtml` (verified). Any authenticated owner can run script in every online member's
   session. Every other render site checked escapes correctly. *Fix: escapeHtml both sites.*
7. **Rule 5 all-pass termination uses a rolling 12-pick window** — `js/app.js:10533-10536`
   and same logic in the cron (verified). 12 consecutive passes spanning a round boundary
   (possible from only ~6 teams under snake reversal) ends the draft mid-round, denying
   remaining teams their turns. *Fix: only test at round boundaries (`N % numTeams === 0`).*
8. **Notifications permanently lost on transient failures** — `notify_draft_clock.py:381-389,
   417-435` and `notify_key_date_reminders.py:130-140`: markers recorded even when the prefs
   fetch failed (treats everyone as opted out) or when every SMTP send raised. One Gmail blip
   during a draft = on-clock alert never retried. (`notify_instant.py` does this right.)
9. **ESPN sync txLog validation accepts error bodies** — `scripts/sync_espn.sh:62`:
   `.transactions? // [] | type=="array"` is true for ANY JSON, so an ESPN 200-with-error-body
   for one scoring period ships a silently-partial txLog — the exact condition the code
   comments say must abort (keepers reprice as FAs). Also `.topics | length` passes on missing
   key → snapshot with zero events. *Fix: require the key to exist (`has("transactions")`).*
10. **All owners can read every owner's notification email** — `supabase/schema.sql:667-669`
    `np_select_all` is authenticated-wide and the table has `email` (verified); client
    fetches `select("*")` (`js/db.js:198`). Low harm in a 12-friend league; still fix by
    splitting the email column read to own-team + commish. `test_rls_negative.py` doesn't
    cover it.
11. **Realtime channel has no error/reconnect handling** — `js/db.js:586` subscribes with no
    status callback, no `setAuth` on token refresh, no visibility/online re-sync. Sleep/JWT
    rotation silently freezes live data until hard reload — worst during a live draft.
12. **applyRosterAdjustments ordering: trades before roster_moves** — `js/app.js:357-436`.
    Call-up then trade duplicates the player onto both teams' callups (agent-confirmed).
    *Fix: merge trades + roster_moves chronologically.*
13. **getTeamMilCount double-counts made minors picks** — `js/app.js:159-167` adds
    `draft.picks` on top of `team.minors` that `applyRosterAdjustments` (444-466) already
    populated with those picks (verified). With `enforceMinorsRosterSpot` on, blocks picks ~2
    slots early.
14. **Draft reset doesn't clear `notify_draft_marker`** — reset deletes `draft_2027` only
    (`js/db.js:950-956`); stale markers suppress the new draft's first alerts for teams
    landing on the same pick keys. (Marker manually cleared today; the flow bug remains.)
15. **Daily/weekly digests: windows anchored to actual run time, no idempotency marker** —
    `daily_report.py:118-119`, `weekly_report.py:37-38`. GH cron jitter drops or duplicates
    events; any manual re-run double-sends every digest.

## Tier 3 — low severity / needs Jeff's ruling

- **Keeper-clock anchor inconsistency** — `js/app.js:3392-3393` vs `3504-3505`: drop/re-add
  guard anchors on original MiLB draft year; priced-callup path anchors on call-up year.
  Same player shows different keeper eligibility depending on transaction history.
  **Needs a constitution interpretation from Jeff before "fixing" either way.**
- Luxury-tax freeze window uses viewer's local timezone, not ET (`js/app.js:1929-1930`).
- Digest recipients: broadcast email REPLACES owner emails (instant path augments); josh-doug
  broadcast address gets the digest twice (`daily_report.py:137`, `weekly_report.py:54`).
- `build_export.mjs:452-473` pick-owner walk missing `pickOriginalOwner` pin + legacy value
  parsing → Sheet's Minor League Draft tab can reassign the wrong duplicate pick.
- `notify_instant.py:170-176` strict `>` marker + limit=500 page boundary can skip a row
  sharing `created_at`; `weekly_report.py:39` limit=5000 exceeds PostgREST max-rows (1000).
- `nightly-sync.yml` lacks a concurrency group; can conflict with espn-sync commits (self-heals).
- Malformed `clock.startedAt` → `parse_ts` returns None → AttributeError crashes every cron
  run until manually fixed (`notify_draft_clock.py:116`).
- Digest/alert emails embed unescaped player names / vote titles (`_email_template.py:73,174`)
  — HTML injection into league emails by any member (trusted group).
- `is_email_invited()` is an anonymous invite-list oracle (by design; informational).
- Cron doesn't normalize `rounds` like `_normalizeDraft` does (phantom rounds 8+ if stored
  value ever diverges from 7).
- `undoRule5Pick` orphan-trade fallback can never match (`js/app.js:10787-10800`) — undo
  within the insert round-trip leaves a phantom $1 trade.
- Python ET fallback treats all March/November as EDT (only matters without zoneinfo).
- `touch_updated_at()` lacks `set search_path` (consistency hardening).
- `test_rls_negative.py` coverage gaps: push_subscriptions reads, trade_proposal_messages,
  draft_events, trades/trade_proposals updates, league_votes update, prefs email read.
